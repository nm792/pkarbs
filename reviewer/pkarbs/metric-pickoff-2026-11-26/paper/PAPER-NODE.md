# Metric-release stale-ask pickoff: Nautilus paper node, design, calendar, tests (26 Nov 2026)

**Goal:** reliably $200/day automated Polymarket edges, stacked. **Where we stand:** no MEASURED or SIM figure; the only own-book evidence is one release (25 Nov Core PCE, SIM +$29.60, P158/P159, one release, not a $/day figure) and a prints-only floor in `../README.md` (commit fdc6d9fe5b). **Item that matters most:** this node produces SIM fills, fees and P&L from day 1 on every scheduled event, so depth/edge is measured on several events a week, not on 4 and 10 Dec.

## 1. Design (per Nick 04:45Z and 04:46Z)
1. **Before the release, for every market of the event, BOTH tokens (YES and NO) have a held order**, built locally and not posted, re-sized from that token's live OWN best ask (`HeldOrders.reprice` on every order-book delta; YES and NO books separate).
2. **On the number a lookup table decides EVERY market** (`truth_table`): YES token where the outcome is now true, NO token where it is now false. Brackets (exactly 0.3%), ladders (0.3% or more / 0.2% or less), thresholds (above/below X), "between" all resolve from the same number. A market whose question cannot be parsed, or where the number sits on a "between" edge, is **skipped, never guessed**.
3. **All resulting orders go out in one `SubmitOrderList`** (chunks of 15). Each order: marketable limit BUY, limit 0.95, IOC, shares = $200 / own ask; only if that token's own ask < 0.95; $2,000/UTC-day cap on intended stake, highest edge first.
4. **Nautilus does fills, fees and P&L** (backtest/sandbox matching engine, `PolymarketFeeModel`, which implements fee = C x feeRate x p x (1-p), the formula on [docs.polymarket.com/trading/fees](https://docs.polymarket.com/trading/fees.md); Economics 0.01, Finance/Tech/elections 0.05, Mentions 0.01). Our code has no fill, queue or fee logic. `daily_report.py` only settles Nautilus's fills at resolution.
5. The book recorder (`it/pm_event_books.js`) stays as the AUDIT TRAIL: a daily check that each paper fill's price and size existed in the recorded real book. Not the main step.

## 2. Polymarket docs facts (read 26 Nov)
- **Batch:** `POST /orders`, maximum **15 orders per request**, processed in parallel ([Post multiple orders](https://docs.polymarket.com/api-reference/trade/post-multiple-orders.md)). A CPI day has 4 events and 39 markets (about 39 winner orders) so ~3 requests, sent concurrently.
- **Rate limit:** per signer, 1 token per order, Standard tier 40/s burst 60 (30-day volume tiers above), warning mode from 24 Jul 2026, enforcement date TBA ([limits](https://docs.polymarket.com/api-reference/trading-rate-limits.md)). 39 orders fits one burst on Standard.
- **Can a pre-signed order's price be changed without re-signing? No.** The signed Order carries tokenId, makerAmount, takerAmount (price and size), side, timestamp and salt ([Place Orders](https://docs.polymarket.com/trading/place-orders.md)); only `expiration` sits outside the signed typed data. Re-pricing means re-signing (a local signature, no network call). Two ways to keep a ready order: (a) re-sign in the background on every ask change so the held order is always current, (b) sign once at limit 0.95 with a fixed share count; because price improvement goes to the taker the fill is at the real ask (spend <= 0.95 x shares). The strategy sizes from the live ask, so (a).
- **Nautilus adapter signs at submit time** (`adapters/polymarket/execution.py::_sign_orders_for_batch`, one `create_order` per order in a thread, logged as "Signed n orders in X s"). So in Nautilus 1.231 "preloading" is pre-built Order objects, not pre-signed ones; true pre-signing needs a change to the live adapter path and is UNVERIFIED. Paper/sandbox has no signing, so paper results are unaffected; the signing time is a live-stage cost to read from that log line.
- **Delays:** taker delay 250 ms on selected crypto/finance up-down markets; sports/game seconds-delay; held orders cannot be cancelled ([Order Lifecycle](https://docs.polymarket.com/concepts/order-lifecycle.md)). Macro markets read `seconds_delay` 0 on 24 Nov (SPEC). Re-read per market before each release.
- **Cost flag:** the Nautilus adapter attaches a hard-coded builder code to every live order (`POLYMARKET_NAUTILUS_BUILDER_CODE`); Polymarket builder fees are additive to platform fees ([Builder fees](https://docs.polymarket.com/programs/builders/fees.md)). Rate unknown. Irrelevant for paper; must be settled before any live money.

Counter-Strike 2

Low Latency feed details for Counter-Strike

The CS2 Low Latency Feed gives you access to live match data ahead of the live stream. CS2 is a round-based game, which makes real-time round scores and side assignments (Terrorist vs. Counter-Terrorist) especially valuable signals. This page covers the CS2-specific payload structure, field reference, and links to historical and post-game data. For connection setup, status lifecycle, and rate limits, see the Low Latency Feed overview.

Updates are pushed on every state change, not only at round boundaries. For example, if a player's HP changes, an update is pushed. The payload contains the full match structure, including all games (maps), current round scores, team sides, player and team round state, previous rounds, and game statuses.

Additionally, status change messages are sent when a match or game status changes (see status changes)..

Available Fields

Every payload includes an available_fields array that tells you which live round enrichment fields are currently populated. Basic data (match/game IDs, statuses, team names, and the updated at) is always present. available_fields applies only to the richer in-round data points like player alive status, sides, bomb state, player stats and economy.

"available_fields": [
  "bomb",
  "map_id",
  "player_alive",
  "player_name",
  "round_score",
  "round_timer",
  "side",
  "player_kills",
  "player_deaths",
  "player_armor",
  "player_health",
  "player_weapons",
  "player_current_money_balance",
  "player_loadout_value",
  "current_money_balance",
  "loadout_value",
  "buy_phase_main_weapon_value",
  "rounds_summary"
]

Key behaviours:

  • Dynamic during a match — the list can change between payloads. A match may start with only basic fields and expand to include richer data mid-game, or vice versa.
  • Fallback mode — if PandaScore experiences a technical issue, the feed falls back to a basic data set. In this case, available_fields will contain only map_id, round_score, and round_timer. You should always check available_fields before consuming enrichment fields.

Latency

Every payload includes a latency array with the estimated delay of each data point, in milliseconds, relative to the fastest data point. If a data point is not in the feed, it is not included in this array.

"latency": [
  { "field": "round_timer", "delay": 0 },
  { "field": "round_score", "delay": 30 },
  { "field": "player_weapons", "delay": 1800 }
]

Key behaviours:

  • Relative to the fastest data point — at least one data point always has a delay of 0. For CS2, the round score is usually the fastest.
  • Delays differ by data point — the feed aggregates multiple data sources and pushes each data point as soon as it is available, so data points can arrive at different times. You can use latency in your models to account for this. For example, if player_kills has a delay of 5000, kills are about 5 seconds behind the fastest data point.
  • Delays differ by match — the delays may differ between matches and games, so ensure that you check this data point in each match.
  • Round changes reset the slate — when the round score changes, some data points still lagging behind are reset, so the payload stays coherent.

Additional Post-Game Data

You have access to all post-game and historical CS2 data to help improve your strategy, including:

  • Get a CS2 Game — to get post-game data, wait until the game status is marked as finished and complete=true. See our FAQs to learn more.
  • Get stats for a CS2 player — aggregated player performance statistics.
  • Get stats for a CS2 team — aggregated team performance statistics.

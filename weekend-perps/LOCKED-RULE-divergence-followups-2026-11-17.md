# LOCKED RULES: three follow-ups on perp divergence from the oracle/index (17 Nov 2026, written before any number of these tests was computed)

Origin: Nick, 17 Nov 02:07Z ("and?"), after RESULT-funding-window-divergence-2026-11-17.md. Common cost model (unchanged from LOCKED-RULE-funding-window-divergence): taker fee 9 bp per side on Hyperliquid builder dexes (4.5 bp base doubled); Polymarket equity/index taker fee 4 bp per side (no tier discounts). Spreads are measured from real order books (test 1) or live l2Book half-spreads stressed 3x with a 1 bp floor (tests 2, 3). Bootstrap = weekly-cluster for history, event-cluster for the live tests, 10,000 resamples, seed 1.

## Test 1: fade Polymarket after-hours stock gaps at real book prices (forward data, 5 s logger)
Data: a new logger (weekend-perps/pm_hl_5s_logger.py) records every 5 s: Polymarket tickers (index, mark, mid, last) for ALL equity and index perps, and for any symbol whose |mid - index| >= 20 bp, plus NVDA, MU, AMD, TSLA and SP500 always, the top 10 levels of /v1/info/book; also Hyperliquid metaAndAssetCtxs for xyz, flx, km (mark, oracle, mid) for all symbols. Runs continuously; the evaluation uses only the sessions recorded after this rule is merged.
Gap g = (mid - index) / index in bp. Signal at the first 5 s sample with |g| >= 25 bp for a symbol with no open trade. Position = against g (sell if g > 0, buy if g < 0).
Entry: at the NEXT 5 s sample (5 s latency), only if |g| is still >= 15 bp there; fill = VWAP of $1,000 notional walked through that sample's book on the far side (ask to buy, bid to sell). Exit: the first sample with |g| < 5 bp, or 300 s after entry, whichever is first; the fill is at the book of the sample after that trigger (another 5 s latency), VWAP of the same notional. Gross = position x (exit/entry - 1). Net = gross - 2 x 4 bp - funding paid if a top-of-hour settlement is crossed (rate from /v1/info/funding). Missed trades (gap gone at the entry sample) are counted.
Placebo: for each event, one random entry time in the same symbol during the same session with |g| < 10 bp, random direction, same exit rule, same costs (seed 1).
Decision: PASS only if >= 30 events over >= 2 calendar days AND mean net > 0 with the 95% bootstrap CI lower bound > 0 AND mean net exceeds the placebo mean. With fewer events or one day it is labelled PRELIMINARY and the number of events and days needed is stated.

## Test 2: carry, hold the faded side across several settlements (history)
Data: hist.json and cand.json from followups-2026-11-17 (hourly premium, funding rate, 1 h trade candles; 108 perps on xyz, flx, km).
Event: end of an hour with |premium| >= 50 bp. Position against the premium sign, entered at that hour's closing candle price, held for k = 6 hours (primary), exited at the close of hour +6. Net = price move x position + funding received over the 6 settlements (funding = position x -rate; on flx the rate is as recorded) - 2 x (9 bp + max(3 x live half-spread, 1 bp)). Sensitivity reported only: k = 3 and 12. Events are only allowed if no earlier event of the same symbol is still open (non-overlapping).
Subsets: (a) dex xyz vs flx+km; (b) OI tercile (thin / mid / liquid, same cut-offs as before); (c) "persistent" events where |premium| >= 100 bp of the same sign for 3 consecutive hours before entry (the BIRD pattern).
Decision: PASS for a subset only if n >= 30 non-overlapping events over >= 8 calendar weeks AND net mean > 0 with 95% CI lower bound > 0. Else "no tradable carry".

## Test 3: frozen oracles, the reset jump (history, descriptive plus one ex-post bound)
Episode: a maximal run of >= 3 consecutive hourly premiums with the same sign and |premium| >= 100 bp. Reset = the first hour afterwards with |premium| < 25 bp.
Report: (a) distribution of run length and of |premium| before the reset, by dex and tier; (b) hazard: P(reset in the next hour | run length n) for n = 3..12; (c) the perp's own 1 h candle return in the reset hour, signed toward the oracle (that is, x -sign(premium)), versus the premium before the reset: mean, median, and the regression slope (1.0 would mean the whole gap is closed by the perp price, 0 would mean the oracle moved to the perp); (d) predictability: logistic regression of "reset in the next hour" on run length, |premium| and an hour-of-day/weekend indicator, with out-of-sample AUC on the last 30% of weeks.
Ex-post upper bound (not tradable, because the reset hour is unknown in advance): enter against the premium at the close of the third hour of the episode, exit at the close of the reset hour, same costs. If even this ex-post bound is not net positive, "no tradable jump" is the answer.
What the venue settles or liquidates against when the oracle unfreezes: the trade.xyz and Hyperliquid documentation hosts are blocked from this container, so this is reported as not verified from docs; the API fields (markPx, oraclePx, midPx, funding, openInterest) show what is observable. No claim beyond that.
No threshold or definition in this file may change after the first number is seen; any new idea needs a new rule file.

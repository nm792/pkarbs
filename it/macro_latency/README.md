# Macro pickoff: per-fill latency table (Nick 26 Nov: why does P&L rise from +$29.60 at 0.5 s to +$43.12 at 5 s?)
Read-only, paper only. Needs the PCE release folder written by pm_event_books.js (markets.jsonl + books-*.jsonl.gz) on Prime and the winners file used for P159. The P159 books are NOT in the repo, so I could not run it.
Run (IT, Prime): cd it/macro_latency && python3 -I test_macro_latency_table.py && python3 -I test_macro_pickoff_score.py && python3 -I macro_latency_table.py <PCE_DIR> 2026-11-25T13:30:00Z <winners.json> 0.5,2,5 > pce_latency_table.jsonl
Paste pce_latency_table.jsonl (14 markets x 3 latencies = 42 lines, a few KB). Expected write: none beyond that file. macro_pickoff_score.py here is byte-identical to reviewer it/macro_pickoff_score.py at 6f7d6bad3c; if P159 used another scorer, say which.
Columns: L, market, winner, result, token, ask, ask_size, row_age_s (decision time minus the book row's receipt time), level_first_seen_after_R_s, available_at_Lmin (False = liquidity a faster bot could not have bought), price, shares, stake, pnl.
Verdict rule: (a) lookahead = the tool raises AssertionError('LOOKAHEAD') or any row_age_s < 0 (cannot occur: last_at only returns rows at or before the decision time); (b) = a FILLED row at L=5 with available_at_Lmin False; (c) anything else (clock offset between recv_ms and the release time, a different scorer, fill size taken from a later row).
